01 Shipped

Sanctions — the “Disable” call-block

No new field needed — member-client already enforces this, and we now mirror it. The block isn’t a pre-call query; it’s the HTTP 403 the member-call endpoint already returns for a disabled account, with the reason in the body (member-client’s SanctionedError). We were mapping that 403 onto the 401 branch — which signs the member out instead of telling them why. Now split: 401 → sign back in, 403 → show the reason (fallback “This account is currently blocked from requesting legal support.”), terminal, not retryable, no logout. Both platforms, on dev.

One confirm → that the gateway returns 403 (not 401 / 423) for a Disabled account, with the member-facing reason in the response body (member-client treats it as plain text; so do we).

02 Shipped

Financial Status

Also shipped without a new field. There’s no authenticated myFinancialStatus today — financialStatus lives only on the pre-login purchaseEligibility funnel, which the native apps don’t use. member-client realises the taxonomy for a logged-in member on PaymentAndPlanScreen from the membership statusCode it already has — so we do the same: the plan card now shows a precise badge — Active / Trial / Payment overdue / Paused / Canceled / Expired / Grace period — with canceled ≠ expired distinguished (the gap your #141 fixed on web; our card previously showed nothing for a non-covered member). Both platforms, on dev.

If you later expose an authenticated financialStatus on the account/entitlement, keying on it directly is a one-line switch — but nothing’s needed from you for this to work now.

05 Shipped

Documents — fields, icons, order

Fields, the three new ones (state_of_issue, gun_owner as dropdowns; health_conditions as text), their options (both JSON-string and array shapes) and both sortOrder levels already render, and a failed load is never swallowed as empty config.

Icons — reversed our earlier call: we now honour the admin icon. Your note that these are Lucide names, not raw images, is what unblocked it — we mirror member-client’s IconValue: an http(s) URL is loaded, a Lucide/Feather name maps to a local glyph (iOS → an SF Symbol; Android → the nearest bundled section glyph), otherwise we fall back to our per-type glyph. Names are normalized the same way (camelCase / snake_case / spaces). One asymmetry: iOS also renders URL icons natively; Android needs an image loader (Coil) wired before URL icons show — a small follow-up on our side. Lucide-name icons work on both today.

Country scoping — shipped. adminDocumentFieldList now carries the member’s current country (device region), like member-client; fields such as state_of_issue can vary by country. The types list stays global (no country arg), matching the reference. Null region → your global set, exactly as the web client’s code || null.

Family members · screen 33B

Included seats are addable without a seat price

Separate from the six — a bug we found and fixed while comparing 33B to member-client. The screen required a seatPriceId to add any sub-account, so a member with only included (free) spots saw “no seat price configured” and no Invite. Matching member-client, a price is required only for additional (beyond-included) seats; included ones send none. Fixed on both platforms — every open included spot now shows the Invite action.

We also gated the whole screen on isSubaccount (you confirmed the field exists): a family child can no longer add or manage members — otherwise a sub-account could invite strangers onto the primary’s plan. They now see a “Managed by the primary account” card instead, and the Family row is hidden from their overview. And we now fetch maxAdditionalSeats / additionalSubaccountFeeCents.

Still open: paid additional seats (beyond the included ones) need a seatPriceId, and we don’t know where it comes from on mobile — member-client resolves it with findSeatProduct over the price catalogue, which ties into your Finance work. See the ask below.
