## Key findings

### 1. `member-client` is not the visual reference
Its CSS is blue/violet — `--asi-accent: #4f7cff`, `--asi-accent-2: #7a5cff` on
`#0b1020`. The PDF explicitly lists Bright Purple `#7B2FBE` under colours to
avoid ("reads as tech startup or fintech, weakens the legal authority signal").
So: **behaviour and API from `member-client`, colour from the PDF, layout from
the CodePen.** Recorded as an authority order in CLAUDE.md.

### 2. The PDF's own CTA styling fails WCAG AA
Computed contrast ratios for every pair the app needs. Three failures:

| Pair | Ratio | Verdict |
|---|---|---|
| White on Justice Gold `#C4850A` | **3.13:1** | Fails AA normal text (needs 4.5) |
| White on Active Gold `#E8A020` | **2.22:1** | Fails outright |
| Mid Navy `#1A3A5C` on Shield Navy | **1.49:1** | Invisible as text |

The PDF's live-site preview shows a gold "Get Protected" button with white
text — reproducing it would ship a WCAG failure on the app's most important CTA.
Resolution: **Shield Navy on gold (5.53:1)**, encoded as the `ctaFg` token.

The PDF also assigns Mid Navy to "secondary text on dark", which at 1.49:1 is
unusable. Steel Blue `#8DA8C4` (7.03:1) is the correct token for that role — the
PDF itself assigns it to "muted text on dark". Treated the Mid Navy note as a
source error and documented it.

### 3. The CodePen palette contradicts the PDF
Both golds and the primary navy agree; three values do not:

| Role | PDF (wins) | CodePen |
|---|---|---|
| Secondary dark | `#122440` | `#0A1626` |
| Success | `#1E7A48` | `#2E9E5B` |
| Steel/blue | `#1A3A5C` / `#8DA8C4` | `#1A5FA8` |

The user's instruction ("always use the palette in the PDF") settles it. Listed
in the plan's open questions so Blue Sky Marketing can confirm which is stale.

### 4. Scope far exceeds the available API — the big one
The CodePen specifies **35 screens, 5 stages, 3 user types** (Standard Member,
7-Day Limited Trial, Guest), a paywall (`$19/mo`, `$179/yr`, `$29/mo` family),
an app↔web handoff, and a nudge system. `member-client` implements **3 screens**.

Every documented operation is: `login`, `user`, `casesByUser`,
`adminIncidentTypeList` + `adminLanguageList`, `partnerAttorneys`, and
`POST /api/vonage/video/member-call`. **There is no endpoint for sign-up,
payment, subscription, trial activation, or guest sessions**, and CLAUDE.md
forbids inventing endpoints.

So roughly two of five stages are **blocked on backend work that does not
exist**, not merely unbuilt. The plan phases around this: Phases 0–2 deliver the
login → home → call spine that the API does support; Phase 3 is deliberately
unestimated pending a decision. The CodePen's "App ↔ Web handoff" badge suggests
onboarding may be intended to stay on web with the app deep-linking into it —
which would cut native scope substantially. That is the highest-value question
to settle.

### 5. No token refresh exists
`login` returns a `refreshToken` but `api.ts` never sends it and no refresh
operation is documented. Native apps stay backgrounded far longer than a web tab,
so this hurts more here than on web. Flagged as a Phase 1 spike.

## Decisions and why

**Palette committed as `design/color-system.md`, not just prose in the plan.**
It needs to outlive this conversation and be citable from both app repos. The
contrast table is in it so the numbers are checkable rather than asserted.

**Contrast turned into automated test gates (T-DS-1..5), not review checklists.**
A reviewer will not notice 3.13:1; a test will. Includes negative assertions that
the three failing pairs are never formed.

**Kept `danger`/error colour deliberately unresolved.** The palette forbids
`#FF4500` and supplies no error colour, but the call flow needs an error state
and a hang-up control. Inventing one would violate "always use this palette", so
it is an open question with a safe interim (neutral outlined hang-up, no
unapproved colour ships).

**Raw `POST /query` over Apollo/codegen** on both platforms — faithfulness to
`api.ts`'s hand-written queries matters more than codegen, and we do not have a
schema to generate from.

**Phase 0 includes a Vonage native spike.** The reference uses the *web* SDK
(`@vonage/client-sdk-video`); native needs the Vonage Video Android/iOS SDKs.
If the `apiKey`/`sessionId`/`token` triple does not connect natively, Phase 2
estimates are invalid — so prove it before building on it.

## Addendum — CodePen inventory landed; plans revised

`notes/design-reference-codepen.md` (1,118 lines) now holds a verbatim
screen-by-screen inventory. Extraction note for future reference: the `/full/`
view is a cross-origin iframe, but the **editor** page (`/pen/YPNOGaM`) exposes
the pen source in a same-origin CodeMirror instance, which is both faster and
strictly more accurate than OCR-ing screenshots.

Four corrections to what I wrote earlier today:

**1. Counts.** The board is **66 phone frames — 9 web-chrome, 57 native**, not
the "35 screens" its masthead claims (35 is just the highest plain number;
letter variants and the V/T/G series push it far higher). Verified by counting
headings myself: the inventory's own summary said "56 native / ten web", which
was slightly off.

**2. Only Stages 1, 4 and 5 exist.** My earlier "roughly two of five stages
blocked" framing was wrong — there is no Stage 2 or Stage 3 header anywhere.

**3. Payment is on the web, and this was the answer to my biggest open
question.** Plan choice, Stripe checkout and confirmation are pages on
`attorney-shield.com`; a deep link returns the member with email pre-filled and
native registration resumes at screen 08. **We do not build checkout.** The web
frames wear a "Native App" badge only because they sit inside the Stage 1
section — a labelling bug, and there is an unused "Web" badge style in the
stylesheet to prove it.

This moves the blockage rather than clearing it: screens 08–12 (phone, OTP,
details, address, PIN), the document vault, situations, activity, family
sub-accounts, nudges, and the trial/guest gates still have **no endpoints**.

**4. Prices were wrong.** The app uses **FreedomPlus $16/mo** and
**FreedomFAMILY $38/mo** plus a $0-today trial. The `$19`/`$179`/`$29` I cited
came from the colour PDF's marketing-site preview — a different surface.

### Added to the plans
- **App Store / Play compliance risk**, now the top risk: selling a digital
  subscription through web Stripe and deep-linking back runs straight into
  Apple's external-payment rules. A rejection invalidates the flow rather than
  delaying it, so the store strategy needs settling before Phase 3, not at
  submission. The reference already anticipates part of this (33A carries
  App Store's required delete-account wording; no in-app plan changes).
- **Deep links promoted to a Phase 2 deliverable** with eight test cases
  (T-D-1..8), including replay-idempotency and rejecting foreign-origin links —
  a deep link is untrusted input and must not grant entitlement.
- Family capacity flagged as genuinely unresolved (stated four ways: "up to 5" /
  "includes 3, add up to 2" / "You + 3" / "You + up to 4" / "3 of 5"). Blocks
  the member stepper.
- Frame geometry is 292x600 px, not the labelled 375pt (rescale ~1.284x).

### Corroboration on the palette
The CodePen sets text on gold buttons to `#1c1304` — near-black, i.e.
dark-on-gold, not white-on-gold. So both references agree in substance and only
the PDF's marketing preview disagrees. Rule R1 stands; we use Shield Navy so the
value stays inside the approved palette.
